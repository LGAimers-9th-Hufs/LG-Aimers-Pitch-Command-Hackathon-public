## 2. 규칙 §2-4 — 추론 코드의 평가 데이터 예측 원칙 (원문)

> **4) 추론 코드의 평가 데이터 예측 원칙**
>
> - 평가 데이터(test.csv)의 각 행은 하나의 독립적인 예측 대상입니다.
> - 참가자는 각 행에 포함된 입력 변수와 주최 측이 제공한 공식 학습 데이터만을 이용하여 해당 행의
>   예측값(제구 성공 확률)을 추론해야 합니다.
> - 평가 데이터의 다른 행이나 전체 평가 데이터의 분포를 이용해 특정 행의 예측값을 보정하거나 생성하는

**우리 대응**: 세 문장 각각에 기계 검사가 하나씩 붙어 있다.

| 규칙 문장 | 우리 강제 수단 |
|---|---|
| 각 행은 독립적인 예측 대상 | `sweep/test_regulation.py::test_row_independence` — 단일 행 예측 == 전체 프레임 예측 |

## 5. 우리 해석 — 범위에 관한 3가지 판단

1. **추론 코드는 다시 낼 필요가 없다.** 규칙이 "추론 코드는 리더보드에 제출한 추론 코드로 대체"라고
   명시한다. 따라서 요구물은 **제출 zip의 `model/`을 만들어내는 학습 코드**다. 우리는 그럼에도
   서빙 템플릿과 검증기를 함께 넣는다 — 재현자가 zip을 다시 조립해 대조할 수 있어야 하기 때문이다.
2. **재현 대상 = 팀 4레그 전체.** 우리 제출물은 세 사람의 파이프라인을 확률 평균한 것이라,
   본 저장소 코드만으로는 절반(physmix·tm3L)밖에 재현되지 않는다. 팀원 저장소 코드를 커밋 해시
   고정으로 동봉한다(`TEAM_REQUEST.md` ④ 동의 필요).
3. **PPT는 선발에 직접 영향이 없다**(동일 시리즈 대회 공지 문구). 따라서 마감이 빡빡할 때
   **코드 패키지가 우선**이고 PPT는 그 다음이다. 단 심사 가산점 축("새로운 제구력 평가 시각")은
   PPT에서만 전달되므로 분량이 아니라 내용으로 만든다.
