## 2. 그런데 지금 제출이 불가능하다

산출물이 **2021~2024 검증 예측**뿐이다. 실제 대회 제출은 **2025 평가셋 245,789행을 서버에서
행 단위로 추론**해야 하는데 그 경로가 없다. 즉 지금 상태로는 위 +10.31을 **한 점도 실현할 수 없다.**

**이번 라운드는 모델을 더 건드리지 마라.** 라운드 2 최종본(monotone hierarchical two-seed)을
그대로 **서빙 가능하게 포장**하는 것이 전부다.

## 3. 할 일 = `SERVING_CONTRACT.md` 전문을 그대로 이행

같은 폴더의 **`SERVING_CONTRACT.md`를 읽고 그대로 구현해라.** 요약하면:

```
results/codex_partner/serving/
  predict.py      # def predict(test_df, model_dir) -> np.ndarray  (유일한 진입점)
  <아티팩트>       # LightGBM booster .txt · 룩업 .json/.npz
  MANIFEST.json   # files·sha256·trained_through_season + raw_mean_2024·raw_std_2024
  selftest.py · SELFTEST.md
```

**가장 자주 틀리는 지점 3가지 — 여기서 실패하면 제출 자체를 못 한다:**

1. **§5 배치 통계 금지**: `.mean(` `.groupby(` `.value_counts(` `.transform(` `.rolling(`
   `.expanding(` `.cumsum(` `.rank(` **호출이 하나라도 있으면 우리 검증기가 AST로 잡아내고 탈락**이다.
   전처리에 통계가 필요하면 **학습 때 계산해 상수로 저장**하고 서빙에서는 조회만 해라.
   (계층 수축의 그룹 평균·기준선도 전부 학습 시 상수로 굳혀야 한다.)
2. **미등장 값**: 2025에만 있는 pitcher_id·범주는 룩업에 없다. 반드시 `.get(key, 기본값)` 폴백.
   예외를 던지면 **슬롯이 차감**된다.
3. **커스텀 클래스 pickle 금지**: 서버에 네 모듈이 없다. booster는 `save_model()`, 나머지는 JSON/NPZ.

**학습 범위**: 검증 CSV와 달리 컷오프가 없다. **`season ≤ 2024` 전량**으로 라운드 2 레시피
그대로 재학습해라(시즌 가중 0.25/0.5/1.0이면 2022/2023/2024).

**MANIFEST에 반드시 넣을 것**: 네 서빙 예측의 **train 2024 기준 평균·표준편차**
(`raw_mean_2024`, `raw_std_2024`). 우리가 평균·분산 보존 정규화 상수로 동봉해서
블렌드 가중 `w`만 순수하게 리더보드 프로빙할 수 있게 만든다(계약서 §4 참조).

## 4. 자기 검증 결과를 `SELFTEST.md`에 적어라

- 245,789행 프록시(train 2024에서 생성) 전체 소요 시간 — **60초 이내**여야 한다
- 행수 · NaN 0 · 범위 [0,1] · 예측 평균/SD
- `train_partner.py`의 2024 검증 예측과의 상관 (같은 레시피인지 확인. 학습 범위가 달라
  1.0이 될 필요는 없지만 0.9 아래면 뭔가 어긋난 것이다)
- `predict.py`에 위 금지 호출이 하나도 없음을 grep으로 확인한 결과

## 5. 규율

- **시간 예산 45~60분.** 모델 개선 금지. 포장과 검증만.
- 30분 지점에 `predict.py`가 프록시에서 한 번도 안 돌았으면, 구조를 단순화해서라도
  **동작하는 서빙 경로부터 확보**해라. 정확도보다 실행 가능성이 우선이다.
- 실패하거나 불확실한 부분은 `SELFTEST.md`에 그대로 적어라. 숨기면 우리가 슬롯을 태운다.
