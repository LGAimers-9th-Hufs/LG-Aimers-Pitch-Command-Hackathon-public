## 1. 왜 이런 조건인가 — 블렌드의 산수

두 모델 예측을 평균하면 점수가 오르는 것은 수학적 보장입니다:

```
Brier(평균) = 평균Brier − mean((p_A − p_B)²)/4
```

즉 이득의 크기는 오직 **두 모델 예측의 불일치 RMS(s)** 가 결정합니다. 저희 앵커(≈1016) 기준
**최적 가중 블렌드의 기대 이득표** (행 = 팀원 모델의 LB 점수, 열 = 불일치 s):

| 팀원 점수 \ s | 0.015 | 0.020 | 0.025 | 0.030 | 0.035 |
|---|---|---|---|---|---|
| 1000 | +15 | +33 | +55 | +83 | +115 |
| 950 | +2 | +14 | +34 | +61 | +92 |
| 900 | 0 | +3 | +18 | +42 | +72 |
| 850 | 0 | 0 | +7 | +27 | +54 |

손익분기(이보다 s가 커야 이득): 팀원 1000점이면 s≥0.006 / 950점 s≥0.013 / 900점 s≥0.017 / 850점 s≥0.020.

**⚠ 경고 — 수렴 법칙 (저희가 실측으로 확인)**: 같은 데이터의 같은 정보로 만든 좋은 모델들은
설계를 완전히 다르게 해도 예측이 s≈0.013으로 수렴합니다. 저희가 일부러 설계 축을 전부 뒤집은
독립 파이프라인(다른 피처 체계 + 다른 목적함수 + 다른 부스팅 라이브러리, 단독 830점)을 만들어
봤는데 s=0.0134로 수렴해 블렌드 무가치였습니다. **알고리즘을 바꾸는 것으로는 안 되고,
"모델이 아는 정보"가 달라야 합니다.** 그래서 이 문서의 조건이 "무엇을 쓰지 말라"(§3)에
집중되어 있습니다.

## 2. 반드시 지킬 대회 규정 (위반 시 팀 전체 실격 리스크)

   - ✅ 허용: 각 행의 값만으로 만드는 행 단위 변환 + **train으로 만든 고정 룩업**을 zip에 동봉해 조회

   트랙맨 측정값 / 2025년 트랙맨. (train 라벨은 학습에 당연히 사용 가능 — 입력 피처만 금지)
3. **외부 데이터 금지**: train.csv · test.csv · trackman_history.csv(2019~24)만 사용 가능.
   사전학습 가중치는 공개 라이선스만 (TabPFN 계열은 라이선스상 불가).
4. **서빙 생존 수칙** (실행 오류 = 제출 횟수 차감):
   - 커스텀 클래스를 pickle에 넣지 말 것(서버에 그 모듈이 없어 언피클 실패) — 순수 sklearn/

   - requirements.txt로 설치 검증된 조합 사용 (lightgbm==4.6.0은 서버 설치 확인됨)
   - 추론 10분 제한 (245,789행)
5. **Phase 3 대비**: 본선 진출 시 재현용 학습 코드를 제출해야 하므로 **시드 고정 + 재현 가능**하게.

## 3. ⚠ 겹치면 무가치 — 저희가 이미 쓰고 있는 것들

아래와 같은 접근은 아무리 잘 만들어도 저희 모델과 수렴해서 블렌드 0점이 됩니다.
**같은 걸 쓰지 말라는 게 아니라, "이것만으로 만든 모델은 안 된다"는 뜻입니다.**

**학습 구성**: 최신 1시즌(2024)만 학습하는 구성 + 전 시즌 풀링 저가중 멤버 (둘 다 보유)

**피처 계열** (저희 스택에 이미 있음):
- 공식 47컬럼 + 카운트 코드, log(n), 신뢰도 수축률(rate·n+250)/(n+500), prev1/3/5 채움, 손 매치
- **당해 시즌 분해**: 공식 asof 누적치에서 "직전 시즌 말 누적"(train 룩업)을 빼서 당해 시즌
  성적을 분리 — 투수판·타자판·EB판 전부 보유 (이게 저희 점수의 최대 원천입니다)
- 카운트×당해폼 곱 피처, prev 게임 분모 복원(투구수 역산)
- **트랙맨**: 투수-시즌 매칭 후 물리 프로필(구속/스핀/무브먼트), 구종군별 물리×구종믹스 가중,
  카운트×타자손별 구종 선택 성향, 카운트별 물리 변조, 신경망 인코더 임베딩까지 전부 시도함
- 압박(LI)류·홈/매치업·직전시즌 상수·kNN 이웃 통계 — 측정 결과 전부 무효(시간 낭비 방지용 공유)

**모델**: LightGBM·XGBoost·CatBoost·ExtraTrees·RandomForest·선형(원핫+MSE)·MLP·TabM —
전부 측정했고 서로 수렴합니다. **모델 종류 선택은 다양성을 만들지 못합니다.**

**캘리브레이션**: 아핀(slope·shift) 보정 + 리더보드 프로빙으로 절편 최적화 완료.
isotonic은 이 대회에서 해롭습니다(실측 −150 이상) — 쓰지 마세요.

## 4. ✅ 권장 방향 — 다양성이 나올 수 있는 각도

정직하게 말하면 같은 데이터에서 "다른 정보"를 만드는 것은 어렵습니다. 그래도 저희가
**시도하지 않았거나 원리적으로 다른 시각**이 나올 수 있는 방향들입니다 (난이도 순):

1. **세그먼트 분리 모델링** (난이도 하): game_type(정규/퓨처스)·선발/불펜(prev 게임 투구수로
   구분 가능)·투수 경력 구간별로 **완전히 별도의 모델**을 만들어 합치는 구성. 저희는 전 행
   단일 모델 + 피처로만 처리 — 분리 학습은 다른 오차 구조를 만들 수 있습니다.
2. **다른 타깃 프레이밍** (난이도 중): 성공확률을 직접 맞추지 말고 예를 들어 "투수별 기준선
   대비 잔차"를 타깃으로 학습 후 복원, 또는 분위 회귀 등 — 저희는 y 직접 회귀(MSE)와
   이진 logloss만 사용.
3. **사람의 야구 지식 기반 수작업 피처** (난이도 중, 추천): 데이터 명세를 보고 "이 상황은
   이래서 제구가 흔들린다"는 도메인 가설을 손으로 피처화 (예: 특정 카운트 전환 패턴, 주자
   상황×점수차 조합의 세밀한 해석, 이닝×투구순서 조합). 저희는 통계적 파생 위주라 사람의
   상황 해석이 실제로 다른 정보가 될 수 있습니다.
4. **다른 시즌 가중 체계** (난이도 하): 예를 들어 2022~2024를 특정 비율로 섞거나 시즌별
   모델을 만들어 가중 — 저희는 "2024 단독"과 "전체 풀링" 두 극단만 보유. 중간 지대는 미탐색.
5. **트랙맨의 다른 사용법** (난이도 상): 저희는 투수-시즌 단위 프로필로만 씁니다. 예를 들어
   투구 순서·이닝 흐름 같은 경기 내 구조를 train 학습에만 활용하는 방식(추론은 행 단위 유지)은
   미탐색입니다.

**핵심은 방향보다 독립성입니다**: 위 목록에 없는 본인만의 아이디어가 있다면 그게 더 좋습니다.
저희 코드를 참고하지 말고 만들어 주세요 — 판정은 CSV 한 장으로 저희가 해 드립니다.

## 7. 저희가 돌려드릴 것 (CSV 수신 후 ~1일)

1. **불일치 s 실측** + 위 손익표 기준 기대 이득 + 최적 블렌드 가중
2. 판정: s ≤ 0.0134면 "정보가 겹침"(블렌드 무가치 — 어떤 부분이 겹치는지 피드백),
   s가 크면 결합 제출물 빌드·검증·제출까지 저희가 수행
3. 규정 리스크가 보이면 즉시 알림 (제출 전에 고칠 수 있게)

## 8. FAQ

- **Q. 점수가 낮은데 보내도 되나요?** A. 네. 850+ 이상이면 본격 후보이고, 그보다 낮아도
  "다르게 아는" 모델이면 낮은 가중(0.1~0.15)으로 값을 할 수 있습니다(저희 앙상블에는 단독
  319점짜리 멤버도 들어 있습니다 — 불일치가 커서요). CSV만 보내 주시면 판정해 드립니다.
- **Q. 어느 정도 겹쳐도 되나요?** A. 공식 컬럼을 쓰는 것 자체는 당연히 괜찮습니다. 문제는
  §3의 파생 레시피(특히 당해 시즌 분해)를 그대로 재현하는 것 — 그러면 수렴합니다.
- **Q. 트랙맨 써도 되나요?** A. 됩니다. 단 저희 사용법(§3)과 다른 방식이어야 다양성이 나옵니다.
- **Q. 제출 슬롯은?** A. 팀 공유 1일 5회입니다. 단독 점수 측정용 제출이 필요하면 사전에
  조율해 주세요 — 검증 CSV만으로도 대부분 판정이 가능해서 슬롯 없이 진행할 수 있습니다.
- **Q. 왜 굳이 블렌드인가요?** A. 저희 내부 채널은 수십 개 실험으로 소진 상태이고, 남은
  가장 큰 레버가 "다른 정보를 가진 팀원 모델과의 블렌드"이기 때문입니다. 위 표처럼 조건이
  맞으면 +20~60점이 나옵니다 — 저희가 이틀에 걸쳐 판 어떤 채널보다 큽니다.
