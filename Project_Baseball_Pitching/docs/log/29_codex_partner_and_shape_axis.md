## 2. 블렌드 게이트 재설계 — **캘리 상수에 불변인 판정치**

기존 게이트는 고정 캘리에서 `S((1−w)q_A + w·q_B)`를 봤다. 그런데 §1 때문에 **어느 캘리를 쓰느냐로
판정이 뒤집힌다**. 해결은 산수에 있다: 블렌드 뒤 우리가 실제로 하는 일은
`q = a + b·((1−w)p_A + w·q_B)`의 (a,b,w)를 **LB 프로브로 다시 잡는 것**이고, 그 도달 가능 집합은
정확히 `span{1, p_A, q_B}`다. 따라서

```
gain_re = score(proj{1, p_A, q_B}) − score(proj{1, p_A})
```

가 **현재 캘리가 무엇이든 값이 변하지 않는** 불변량이고 이것이 판정치다. 레벨은 `a`가, 스케일은
`b`가 흡수하므로 **파트너의 레벨 오차(전 시즌 학습 시 −362점 우려)는 심사에서 자동으로 무해해진다.**

**⚠ 다만 "심사 기준이 s 하나로 줄어든다"는 것은 틀렸다** (Codex 조사 스레드가 교정). 필요한 것은
`s`가 아니라 **잔여 직교 불일치 `s⊥`와 그 방향의 잔차 상관**이다. `proj_score`가 정확히 그것을 잰다.

**스모크 검증**: 합성 파트너 `q_A + N(0, 0.03)`(순수 노이즈, s=0.0300)를 태웠더니 손익표는 +91을
약속하지만 **`gain_re = +0.22`로 정확히 기각**했다. 항등식 검산 gap −0.002.

**역산**: 방향이 H-직교라 각 프로브가 독립적으로 한 계수를 준다.
`S(d_j 방향 t=1) − S₀ = a_j − C_j` ⇒ `a_j = ΔS_j + C_j`, `t*_j = a_j/(2C_j)`, `G = Σ a_j²/(4C_j)`.
설계가 `C_j = 1`로 정규화돼 있으므로 **`a_j = ΔS_j + 1`, `G = Σ (ΔS_j+1)²/4`.**

**판독**: 여섯 ΔS가 전부 −1 근처면 이 축은 2025에서 비었다(비용 6점, 즉시 종료).
하나라도 ΔS ≥ +5면 그 방향만으로 +9 이상이다.

**공통**: 점수는 `memory/lb-verified-scores.md`에 **먼저 기록** · 반대편 레그는 내지 않는다 ·
곡률 검산이 해석값 ±25% 밖이면 역산 중단.
