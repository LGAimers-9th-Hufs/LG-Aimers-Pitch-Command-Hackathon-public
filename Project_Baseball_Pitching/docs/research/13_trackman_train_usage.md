## §0 요약

- **행 단위 결합은 불가능하다(정량 증명, §1.2).** 유일한 활로 = **투수-시즌 엔티티 매칭** → `(pitcher_id, season)` 키 as-of 고정 룩업을 SERVE 블록 리터럴로 동봉. 규정 §5/§6상 명시적 합법(z_table 전례와 동일 근거 — §6이 trackman_history 2019–24를 사용 가능 데이터로 열거).
- 기대 가치: **투수 해상도/콜드스타트 채널**(oracle 투수 실평균만으로 662점, 현 모델은 투수 스프레드 20% 과수축 — autopsy §1.4)에 결과 이력이 아닌 **물리 측정 신호**(릴리스 반복성, 구위 프로필)를 공급. 측정치는 라벨 표본수가 아니라 측정 표본수에만 의존하므로 저이력 투수에서 상대 가치가 가장 크다.
- 한계 선언: **트랙맨에 2025가 없다** → 2025 신규 등장 투수는 매칭이 원리적으로 불가. 그 층은 train 단독 채널인 **유사투수 kNN(N12, §6)**만 커버한다. 역할 분담은 §2.2.
- 정직한 확률: 매칭 자체 실패(kill 발동) 30–40%, 매칭 성공했으나 게이트 탈락 55–65%(조건부), **최종 제출 스택 도달 ≈ 20–30%**. 1.5일차 go/no-go와 kill criteria를 §7에 고정 — 실패 시 kNN 트랙만 남기고 전면 중단한다.

### 1.3 매칭에 유리한 사실 (2026-08-06 검증 완료)

1. **`asof_pitcher_pitchmix_n`·`asof_pitcher_n`은 100% 커리어 누적 단조** — 792투수 1,468개 시즌 전환 전수에서 위반 0, 시즌 리셋 0. 따라서 투수-시즌 내 최대값 = 시즌말 커리어 누적 → **시즌 증분(=시즌 워크로드)과 시즌말 구종믹스를 정확히 복원 가능**. 매칭 시그니처의 핵심 재료.
2. **손 극성 확정**: train `2`=74.15% ↔ tm `Right`=74.91% → `2`=우투, `1`=좌투 (타자도 동일 극성, `top_bottom`은 T=51.03%↔Top=51.14%로 정합).
3. **팀 구조**: train 1군 10팀은 정규시즌(R) 행이 시즌당 20.4k~23.0k로 균질. **팀 22/23/25는 R 행이 0** → 퓨처스 전용 엔티티(상무·경찰 추정) — 트랙맨의 `KBO_ARM`(25,776행)/`KBO_POL`(902행)과 대응 후보.
4. **KIA 재해석**: `KIA_TIG`는 2019~2024 **전 시즌에서 ~10.4k–11.0k행/시즌**(타 구단 ~21k의 절반)으로 일관. "2022 호크아이 도입 후 결측"(문서 10 §의 추정)이 아니라 **처음부터 홈구장(광주)만 결측, 원정 절반은 기록**된 패턴이다. → KIA 투수도 커버리지 보정(×~2)을 걸면 매칭 가능하며, 절반 볼륨 자체가 KIA 소속 식별 시그니처가 된다. *(문서 10의 해당 서술은 이 수치로 갱신 필요.)*
5. `SK_WYV`(2019–20) → `SSG_LAN`(2021–) 리브랜드가 트랙맨에서 이름 분리 — 팀 매칭에서 단일 프랜차이즈로 통합 처리.
6. `MIN_*` 2군 = 576,879행(32.17%): 1군 시그니처에서는 제외하되, **데뷔 전 2군 측정치의 원천**으로 프로필 단계에서 사용(§2.2). 트랙맨 1군만 = 1,189,400행(66.33%). `ACE_MEX` 등 잔여 1.5%는 완전 제외.

### 1.4 전처리 계약 (구현 시 강제)

- 전 CSV **utf-8-sig**(BOM). `game_date`는 2019–21 `MM/DD/YYYY`(0패딩 불규칙) / 2022–24 `YYYY-MM-DD` 혼재 → `pd.to_datetime(format="mixed")`, 파싱 후 실제 1,057일(2019-03-23~2024-10-17).
- `tagged_pitch_type` 17종 오타맵: {Changeup→ChangeUp, SInker→Sinker, Undefind/Undefined#→Undefined, Four-Seam→Fastball(군 기준)}. 집계는 `pitch_type_group`(fastball/breaking/offspeed/other) 우선.
- `extension ≤ 0`(min −0.387, 물리 불가) → NaN. trackman의 범위 이탈 행(balls 4, strikes 3, outs 3–4, inning 0) → 시그니처 집계에서 클리핑/제외. trackman에만 있는 11월(포스트시즌 추정)은 시그니처 월 분포에서 10월에 병합.

## §2 가치 논거와 역할 분담

### 2.1 왜 이 채널인가

- autopsy §1.4: 투수 커리어 이력 십분위 실측 스프레드 0.1095 vs 모델 예측 0.0881(**20% 과수축**), oracle 투수 실평균만으로 662점. LB 457 → 1위 931의 남은 격차 중 측정된 유일한 대형 채널.
- asof_* 19종은 전부 **결과(성공/실패) 이력의 요약**이다. 트랙맨이 공급하는 것은 그와 직교하는 **원인측 물리량** — 특히 릴리스 반복성(§4의 tm_relstd)은 "제구의 기계적 안정성"을 결과 라벨 없이 측정한다. 800구짜리 신인도 측정 표본은 800개라 추정이 정밀하다 — 콜드스타트 층에서 asof가 가장 약할 때 트랙맨이 가장 강하다.

### 2.2 세 arm의 층 분담 (독립 게이트)

| arm | 공략 층 | 의존성 | 실패 시 잔존물 |
|---|---|---|---|
| **N11 z→GLM 항** | 기존 투수 스프레드 복원 (autopsy §4.4 지정 후속) | 없음 | (pid,season) as-of 룩업 리터럴 인프라 — N13이 재사용 |
| **N12 유사투수 kNN** (§6) | **2025 미등장 신인**(train에 pid 없음 → z_table default로 추락하는 층) + 스프레드 | 없음 (트랙맨 무관) | 프로필 공간 쿼리 인프라 — N13 성공 시 공간 업그레이드(KN_tm) |

## §3 투수-시즌 엔티티 매칭 설계 (`sweep/trackman.py`, 서빙 코드 아님 — AST 제약 없음)

### 3.1 시그니처 공간

행 매칭에 부족했던 공존 컬럼들이 **투수-시즌 분포 시그니처**에는 충분히 풍부하다:

| 채널 | train | trackman | 식별력 |
|---|---|---|---|
| 손 | pitcher_hand(2=R) | Right/Left | **하드 블록** + 극성 자가검증(§3.5) |
| 시즌 워크로드 | 시즌 행수(R/F 분리) + asof_n 시즌 증분 | 시즌 행수(1군/farm 분리) | 강 (커버리지 보정 필요) |
| **월별 활동 바코드** | game_month 투구 분포(8-dim) | 동일 | **최강** — 부상/승격/강등 패턴이 투수별 바코드 |
| 이닝 히스토그램 | inning 분포 | 동일 | 강 — 선발/불펜/마무리 역할 |
| 카운트 상태 분포 | (balls,strikes) 12-dim | 동일 | 중 — 투구 스타일 |
| 요일 분포 | dow 7-dim | 동일 | 중 — **비용함수에서 제외, 검증 전용 예약(§3.6-1)** |
| 구종믹스 | asof 시즌말 3률(§1.3-1로 복원) | pitch_type_group 시즌 비율 | 중 — 분위수 정규화 필수(fastball +4.5%p 계통 오프셋) |
| top/bottom 비율 | 동일 | 동일 | 약 |
| 팀 | team_id 최빈 | 팀명 최빈 | 팀 매칭(§3.3-1단) 후 소프트 비용 |
| 시즌 재적 집합 | 등장 시즌 | 동일 | 강 — 커리어 제약 |

### 3.2 정규화

- 스칼라 축(워크로드, 믹스 3률) = **사이드(손)-시즌-채널 내 분위수 랭크** — 구종 분류 기준 차이(+4.5%p)와 트랙맨 커버리지 결손이 랭크에서 자동 소거.
- 히스토그램 축 = Hellinger 거리(√변환 후 L2) — 표본수 차이에 강건.
- KIA 보정: 팀 매칭 후 팀별 커버리지 비(tm행수/train행수)를 추정해 해당 팀 투수의 워크로드를 보정 카운트로 재산출.
- 정규화→매칭→고신뢰 쌍 기준 분위수 재추정→재매칭 **2회 반복**(모집단 불일치로 인한 랭크 왜곡 완화).

### 3.3 할당: 2단 + 커리어 우선

**1단 — 팀 매칭** (13 id ↔ 26 이름): (팀,시즌,월) 투구량 곡선으로 시즌별 Hungarian → 6시즌 일관성 확인. SK/SSG 통합, MIN_* ↔ 모구단 연결(접두 규칙+볼륨), 퓨처스 엔티티(22/23/25 ↔ KBO_ARM/POL) 대응. 소형 문제라 성공확률 ~90%.

**2단 — 투수 매칭: 시즌별이 아니라 커리어 대 커리어** 792×906 비용행렬 1개를 `scipy.optimize.linear_sum_assignment`(직사각 허용)로:

```
cost(i,j) = Σ_{s∈공존시즌} Σ_k w_k·d_k(sig_i,s, sig_j,s)   # 채널 가중 거리
          + λ_tm·#{s: tm(1군)에만 존재}                      # 강한 비대칭 페널티
          + λ_tr·#{s: train에만 존재}                        # 약한 페널티(커버리지 결손 허용)
          + λ_team·(팀 불일치 시즌 비율)                      # 소프트 — 트레이드 흡수
손 불일치 → +inf (하드 블록)
```

시즌 간 일관성은 커리어 매칭에서 **구성상 자동 충족**되고 6시즌 노이즈가 풀링된다. 시즌별 독립 Hungarian 6회는 **검증용 복제**로만 실행(§3.6-2).

### 3.4 사전 필터

`ACE_MEX` 등 제외(1.5%) / `MIN_*`는 R-채널 시그니처에서 제외하되 F-채널(train F행 대응)로 병렬 비교 + 프로필 단계의 데뷔 전 이력 원천 / `KBO_ARM/POL`은 F-채널 편입. train F 커버리지가 부분적이면 F-채널의 λ_tr=0.

### 3.5 손 극성 자가검증

`2`=Right는 분포 근거 추정이다(74.15%↔74.91%). **양 극성으로 전체 할당을 각각 풀어 총비용 비교** — 옳은 극성이 압도적으로 낮아야 정상. 차이가 작으면 시그니처 붕괴 신호 = 즉시 중단 사유.

### 3.6 정답 없는 검증 — 4중 self-consistency

1. **예약 차원 permutation 검정 (주 판정)**: 요일 분포를 비용에서 **의도적으로 제외**하고 매칭한 뒤, 매칭 쌍의 요일-Hellinger 거리 vs 동일 블록(시즌×손) 내 무작위 순열 분포 → p-값. 비용에 안 쓴 축이 맞아야 진짜 매칭이다. **p ≥ 0.01 → 전체 기각.**
2. **방법 간 합치**: 커리어 매칭 vs 시즌별 독립 6회 — 다시즌 투수의 최빈 tm_id 일치율 **≥ 80%**.
3. **margin**: (2위 비용 − 1위 비용)/스케일, 행·열 양방향 — 분포의 이봉성(확실/애매)이 Tier 컷 근거.
4. **시대 분할 안정성**: 2019–21만 vs 2022–24만 매칭 시 걸친 투수의 쌍 재현율 + 가중치 20회 지터의 쌍 생존율 ≥ 0.9.

### 3.7 Tier 부분 채택

Tier 1(방법 합치 + margin>τ₁ + 지터 생존 ≥0.9)만 프로필 부여. Tier 2/3은 **NaN** — HGB가 결측 분기로 처리("프로필 없음"이 자연 기본값). 매칭 신뢰도 자체는 피처로 넣지 않음(워크로드와 교락, asof_n과 중복).

### 3.8 커버리지 정직 추정

천장: tm 1군 투수-시즌 ≈ 1,800 vs train ≈ 2,230 — **train의 20~25%는 애초에 대응이 없다**. Tier 1 예상 = tm측 60–75% ≈ 1,100–1,350 투수-시즌 = train 투수-시즌의 45–58%, **train 행 가중 60–72%**(고워크로드 투수가 잘 매칭됨). 구조적 긴장: 시그니처 노이즈는 저워크로드에서 최대 = **가치가 가장 큰 곳에서 매칭이 가장 어렵다** — 커리어 매칭(후기 시즌 증거로 확정 → 초기 시즌 소급)이 완화하지만 한계는 남는다.

### 4.1 as-of 설계 — (a) 채택 근거 = 서빙 동형성

**(a) 시즌 s 행 ← s−1까지 커리어 프로필**을 주 설계로:
- train 2024행←≤2023, test 2025행←≤2024 — **train과 serve가 같은 함수형(1시즌 지연)**. (b) 정적 전체(2019–24)는 train 초기 시즌에 미래 프로필을 주고 test에는 못 주는 체계적 비대칭 + 대상 투구 자신의 측정이 자기 시즌 집계에 포함되는 §6 인접 문제.
- 대가: 2019행 전부 NaN(트랙맨 첫해) → **역방향 폴드 refR2019는 트랙맨 피처를 검증하지 못함**(guard 해석에 명시). 데뷔 시즌 신인도 전년 2군 이력이 있으면 프로필을 받는다 — 콜드스타트 채널 보존.
- (b)는 진단 arm 1회만(채택은 (a) 대비 +2×SE 이상일 때만).
- **매칭의 정적성 각주**: 매칭(정체 해소)은 2019–24 전체 시그니처로 1회 계산(라벨 무사용, 공변량 분포만 → 라벨 누수 없음). 다만 V24 폴드 val이 "2024 시그니처가 매칭에 기여한" 정체를 쓰는 미세 낙관 있음 → **민감도 체크: 2019–23만으로 재매칭 시 Tier1 churn < 10%면 안정 선언**, 이상이면 V24 판독 할인.

## §6 train.csv 단독 미개척분 — 유사투수 kNN frozen bank (N12)

**합법 논리**: 뱅크 = train에서 1회 계산해 zip 동봉하는 고정물(z_table의 일반화: 정확 키 → 최근접 키). 각 test 행은 자기 행 값만으로 쿼리, 이웃은 전부 train 투수, test 행 간 상호참조 없음. M31(ModernNCA) 기각 사유는 "뱅크가 test 참조"였으므로 train-only 뱅크는 저촉되지 않는다.

**z_table과의 차이 (존재 이유)**: z_table 키=pitcher_id → **2025 미등장 신인은 default로 추락(정보 0)**. kNN 키=프로필 공간 좌표(손, 시즌말 믹스 3, middle/reverse share, ball−strike, 워크로드 log 등 asof 재조합 12~16dim) → 신인의 행 값으로 "비슷한 기존 투수들"의 credibility 수축 로짓을 빌려온다 — **투수 경계를 넘는 유사도 = 콜드스타트 직격**.

- 뱅크 단위 = **투수-시즌 프로토타입 ~2.6k행**(행 아님 — 행 문맥은 HGB 담당, 부족한 건 투수 축). 값 = `build_credibility` 재사용 수축 로짓 + n.
- 쿼리: 표준화 유클리드(신뢰도 가중 — 각 좌표를 해당 asof 수축계수로 스케일) → k=25 커널 가중 → `knn_logit`/`knn_dist`/`knn_std`.
- 통합: build_features가 아니라 **recal 5번째 항**(BLAS 블로킹의 비트 비결정성이 row-independence 비트 검사와 충돌 방지). `logit p* = a + b·logit p + c·(z−z̄) + d·(t−t̄) + e·(knn_logit−k̄)`, variant명 **KN**. 폴드마다 fit 기간으로 뱅크 재구축(z와 동일 위생).
- 런타임(서버 CPU, 24.6만 쿼리): 2.6k 뱅크 ≈ 5–15초(순수 numpy 청크 GEMM + argpartition, 서브청크 20k — 200k 청크는 거리행렬 2GB라 금지). `.mean()` 메서드는 script.py AST 금지 → `arr.sum(axis=1)/k`.
- 동봉: `calib["knn_bank"]` json(2.6k×16 float ≈ 300KB), 가드형(키 없으면 미발동).
- **시너지**: N13 통과 시 tm 좌표(velo/spin/relstd)를 추가한 두 번째 뱅크 arm `KN_tm` — 물리 좌표는 측정만 있으면 존재하므로 공간 자체가 좋아진다.

**N11 (z→GLM)**: autopsy §4.4 지정 후속의 번호 부여. (pid,season) as-of z 리터럴(792×6시즌, ~30KB)을 만들어 `glm_offset_hgb_z`의 GLM_COLS에 추가 — 재캘리 레이어로 기각된 z(D-11a)를 **레이어가 아니라 GLM 항으로** 재시도. N12/N13 인프라의 최소 선행 구축을 겸한다. **z 생성 시 문서 11의 N22(k를 홀드아웃 예측우도로 스캔)·N23(시즌 경계 ρ 분리, prior 52–74%)을 같은 코드 경로에서 함께 구현할 것** — 모멘트법 τ² 과소추정이 스프레드 20% 과수축의 유력 원인으로 특정됐다.

**⚠ N12 설계 v2**: 본 §6의 초안은 `12_finetuning_rag.md` §2의 **교정 10건**으로 개정됨 — 핵심: 신뢰도는 거리 아닌 평균 가중치에, 쿼리 좌표도 수축, 시즌 내 z-score 좌표, k 스윕, **recal 항이 아니라 HGB 피처 형태가 기본**(행 독립 비트 검사는 (q−B)² 직접합으로 해결), DropoutNet식 콜드 마스킹 학습 필수, 잔차 뱅크(N32)·rookie_comps(N33) 병행. HH 사전 진단(반나절)이 채널 생사 관문.
