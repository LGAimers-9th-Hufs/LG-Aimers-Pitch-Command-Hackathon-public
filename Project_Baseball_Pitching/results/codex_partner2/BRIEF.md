# 작업 지시 — **두 번째** 블렌드 파트너: 첫 번째와도 다른 정보를 써라

## 0. 왜 또 만드나 — 숫자가 명확하다

우리 팀 최고 **1,025.55**, 1위 **1,198.02**, 격차 **172.47**, 마감 **1주**.

첫 번째 파트너(다른 스레드에서 제작, `results/codex_partner/`)는 성공적이었다:
불일치 `s = 0.027~0.032`, 네 폴드 판정치 `gain_re` 평균 **+10.31**. 채택선을 넘었다.

**그런데 그걸로는 172점이 안 열린다.** 블렌드 이득은
`Gain = w(S_B−S_A) + C·s²·w(1−w)`, `C = 402,463`이고, 172점을 열려면 **`s ≈ 0.040~0.045`**가
필요하다. 현 파트너는 0.03이다. 이득은 **불일치의 제곱**으로 커지므로 0.03 → 0.045면 이득이 2.25배다.

⇒ **너의 임무는 "첫 파트너보다 잘 맞히는 모델"이 아니라 "첫 파트너와도, 우리와도 다르게 틀리는 모델"이다.**

## 4. 권장 방향 (네 판단이 우선. 2~3개를 결합해라)

1. **트랙맨을 1순위 정보로 쓰는 모델** (난이도 상, 가치 최대)
   `data/data/trackman_history.csv` (354MB, 2019~2024, 179만 행). **투수 ID 체계가 train과 다르다**
   — 매칭이 선결 과제다(단서: 구종 믹스·손·시즌별 투구수·요일 패턴). 우리는 투수-시즌 단위
   요약으로만 썼으니, **다른 입도**(등판 단위 추세·구종 전환 패턴·시즌 내 궤적)나 **다른 목표변수**로
   쓰면 진짜 다른 정보가 된다. 매칭이 완벽할 필요 없다 — 커버되는 투수만 써도 된다.
2. **시퀀스/흐름 구조를 학습에만 사용** (추론은 행 단위 유지)
   train에는 연속 투구가 순서대로 있다. 그 구조로 학습한 표현을 **행 단위로 조회 가능한 상수**로
   증류하면 §5를 지키면서 새 정보를 넣을 수 있다. 우리도 첫 파트너도 안 했다.
3. **완전히 다른 목적함수**: 첫 파트너는 잔차 MSE, 우리는 y 직접 회귀·이진 logloss.
   분위 회귀 · 순위 학습 · 비대칭 손실 등.
4. **다른 레짐 베팅**: 우리는 "2024 단독"과 "전 시즌", 첫 파트너는 "최근 3시즌 0.25/0.5/1.0".
   비어 있는 곳 = 오래된 시즌 강조 · 시즌별 개별 모델의 비단조 가중 · 특정 시즌 제외.
