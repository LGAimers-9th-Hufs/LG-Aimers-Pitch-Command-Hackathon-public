# 작업 지시 — 블렌드 파트너 모델 제작 (LG Aimers 야구 제구 성공확률 예측)

너는 이 대회 팀의 **블렌드 파트너 모델**을 만든다.
**우리 챔피언을 이기는 것이 목표가 아니다. "우리와 다르게 틀리는 모델"을 만드는 것이 목표다.**

## 0. 왜 이 일이 가치가 있는가 (산수)

두 모델 예측을 가중평균하면 점수가 오르고, 이득은 오직 **예측 불일치 RMS `s`** 가 결정한다.
대회 지표는 Brier Skill 이고 `V = r(1−r) = 0.2484700`, `C = 1e5/V = 402,463` 일 때

```
Gain(w) = w·(S_B − S_A) + C·s²·w(1−w)          S_A = 우리 앵커 LB 1025.55
```

| 네 모델의 LB 환산 | s=0.020 | s=0.030 | s=0.045 |
|---|---|---|---|
| 850 | 0 | **+24** | **+85** |
| 900 | +3 | **+39** | **+146** |
| 1000 | +33 | **+79** | **+205** |

**⚠ 수렴 법칙(우리 실측)**: 같은 데이터의 같은 정보로 만든 좋은 모델들은 설계를 전부 뒤집어도
`s ≈ 0.0134`로 수렴한다. 우리가 일부러 축을 전부 반대로 잡은 독립 파이프라인(다른 피처 체계 +
다른 목적함수 + 다른 부스팅 라이브러리, 단독 830점)을 만들었더니 s=0.0134로 수렴해 블렌드 가치가
0이었다. **알고리즘을 바꾸는 것으로는 다양성이 안 나온다. "모델이 아는 정보"가 달라야 한다.**

그래서 이 작업의 성패는 점수가 아니라 **정보 독립성**이다. 점수 700점대라도 정보가 다르면 값을 한다.

## 4. 지표와 자기 평가

```
score(y, p) = max(0, 1e5 × (1 − Brier(y,p) / (r(1−r))))     r = 해당 시즌 실제 성공률
```

- 우리 앵커는 val 2024에서 이 산식으로 **약 905점**이다. 너는 이걸 이길 필요가 **없다**.
- 로컬→리더보드 전이 실측선: `LB ≈ 0.7541 × 로컬 + 320.9` (잔차 RMS 8). 로컬 700 ≈ LB 850.
- **isotonic 캘리브레이션은 이 대회에서 해롭다**(실측 −150 이상). 쓰지 마라.
  아핀(`p → 0.5 + s(p−0.5) + shift`) 정도만 하고, 그마저도 우리가 나중에 리더보드로 다시 잡는다.

## 6. 절대 지킬 것 — 대회 규정 (위반 시 팀 전체 실격)

1. **평가 데이터(2025 test)의 각 행은 독립적으로 예측되어야 한다.** test 내부의 다른 행을 쓰는
   어떤 피처도 금지 — 누적·롤링·빈도·분포·타깃 인코딩·전체를 본 사후 보정(예측 평균 맞추기 포함).
   ✅ 허용 = 각 행의 값만 쓰는 행 단위 변환 + **train으로 만든 고정 룩업을 동봉해 조회**.
   ⇒ 네 파이프라인이 "2025 test 한 행만 보고 계산 가능한가"를 모든 피처에 대해 통과해야 한다.
2. **입력 금지 정보**: 현재 투구 이후 확정되는 모든 것 / 현재 투구의 위치·판정·결과·구종·
   트랙맨 측정값 / 2025 트랙맨. (train 라벨을 **학습에** 쓰는 것은 당연히 허용, 입력 피처만 금지)
3. **외부 데이터 금지**: `train.csv` · `test.csv` · `trackman_history.csv` 만.
4. 서빙 생존: 커스텀 클래스를 pickle에 넣지 말 것(서버에 모듈이 없어 언피클 실패).
   추론 10분 제한(245,789행). lightgbm==4.6.0은 서버 설치 검증됨.

## 7. 방향 힌트 (조건서 §4 요약 — **네 판단이 우선이다**)

우리가 안 해봤거나 원리적으로 다른 시각이 나올 수 있는 각도:

1. **세그먼트 분리 학습** — `game_type`(R/F) · 선발/불펜(직전 등판 투구수로 구분 가능) · 투수 경력
   구간별로 **피처가 아니라 완전히 별도의 모델**을 학습해 합치기. 우리는 전 행 단일 모델 + 피처로만 처리.
2. **시즌 가중의 중간지대** — 우리는 "2024 단독"과 "전 시즌 풀링" **두 극단만** 보유.
   2022~2024를 특정 비율로 섞거나 시즌별 모델을 가중하는 중간 영역은 **미탐색**이다.
3. **다른 타깃 프레이밍** — 성공확률 직접 회귀 대신 "투수 기준선 대비 잔차"를 학습 후 복원,
   분위 회귀 등. 우리는 y 직접 MSE 회귀와 이진 logloss만 썼다.
4. **사람의 야구 지식 기반 수작업 피처** — 데이터 명세를 읽고 "이 상황은 이래서 제구가 흔들린다"는
   도메인 가설을 손으로 피처화(카운트 전환 패턴, 주자×점수차 조합, 이닝×투구순서 등).
   우리는 통계적 파생 위주라 여기서 진짜 다른 정보가 나올 수 있다.
5. **트랙맨의 다른 사용법** — 우리는 투수-시즌 단위 물리 프로필로만 쓴다. 다만 ID 매칭이 어려워
   시간을 많이 먹으니 **여유가 있을 때만** 손대라.

2~3개를 골라 결합하는 것을 권한다. 위 목록에 없는 네 아이디어가 있으면 그게 더 좋다.

## 8. 규율

- **불일치 s를 최적화 목표로 삼지 마라.** 일부러 다르게 만들려고 모델을 망가뜨리면 안 된다.
  강제 다양성은 문헌(Abe TMLR'24 arXiv:2302.00704 / Jeffares NeurIPS'23 arXiv:2301.11323)과
  우리 실측 모두에서 해롭다고 나왔다. **정직하게 다른 정보로 최선을 다한 결과**만 의미가 있다.
  (s 측정은 우리가 우리 예측으로 직접 한다. 너는 우리 예측을 볼 필요도, 봐서도 안 된다.)
- 시드를 고정하고 재현 가능하게. 학습 코드를 반드시 남겨라.
- **시간 예산 60~75분.** 40분 지점에서 `team_pred_2024.csv`가 없으면 범위를 줄여서라도
  2024 CSV부터 확보해라. 완벽한 4개보다 정직한 1개가 낫다.
- 중간 산출물·실패 기록도 `results/codex_partner/`에 남겨라. 우리가 이어받는다.
