## 3. 🚨 조용한 결함 1건 — 수정함

어제 머지(910b9b3) 체크아웃이 `core.autocrlf=true`로 **파트너 서빙 아티팩트 25개를 CRLF로 변환**했다.
결과: `results/codex_partner*/serving/*.txt`를 LightGBM이 **로드하지 못하고 프로세스가 중단**된다.

- 빌더는 `shutil.copytree` 바이트 복사이고 **sha256을 검사하지 않는다** ⇒ 오늘 파트너 zip을 재빌드했다면
  파트너 레그가 조용히 빠진(=무음 폴백) zip이 나왔을 것이고, 역산 전제가 통째로 거짓이 됐을 것이다.
- 더 나쁜 것: **git 커밋본도 정본이 아니다.** 원본에 있던 진짜 CRLF 2개가 정규화로 소실돼
  MANIFEST sha와 2바이트 어긋난다. **정본은 빌드된 zip 안에만 있었다.**
- 조치: `submit_p2test.zip`에서 25개 복원 → MANIFEST sha256 **전부 일치** 확인 → 로드 OK(260/297 트리) →
  `.gitattributes`에 `Project_Baseball_Pitching/results/codex_partner*/serving/** -text` 추가.

⇒ **교훈: 해시로 봉인된 아티팩트를 동봉하는 코드는 동봉 시점에 sha를 대조해야 한다.**
