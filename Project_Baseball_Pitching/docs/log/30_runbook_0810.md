**좁은 쌍(0.05/0.12)을 쓰는 이유**: Brier는 예측 섭동의 **정확한** 2차식이고 LB는 14자리를 준다.

파트너가 죽어 exact1이 챔피언으로 남으면 그대로 쓸 수 있고, 살면 `--partner`를 붙여 재빌드한다.

## 0. 왜 파트너를 먼저 하나 (순서 정정)

두 축이 준비돼 있다: **파트너 블렌드**(3슬롯)와 **`month_m34` 분할축**(7슬롯).
각 축은 **그때의 베이스 위에서** 계수를 재야 하고, 베이스가 바뀌면 이전 계수는 낡는다.

파트너는 예측을 크게 바꾸고(w=0.5에서 RMS 0.0215) 월 보정은 작다(방향당 RMS 0.0015).
⇒ **큰 것을 먼저 확정하고 작은 것을 그 위에 얹는다.** 순서를 뒤집으면 월 계수가 낡는다.
부수 효과로 **"파트너 채널이 2025에서 살아 있는가"를 첫날에 알게 된다** — 마감이 1주라
이 정보가 남은 예산 배분을 좌우한다(살아 있으면 두 번째 파트너에 투자).

(정규화 이유: 캘리 상수가 raw_A의 레벨·스케일에 묶여 있어, 날것으로 섞으면 블렌드 축과
캘리 축이 뒤섞여 역산이 무의미해진다.)

## 2. 슬롯 ③ — 역산 후 꼭짓점 배포

점수 `S₁(w=0.05)`, `S₂(w=0.12)`과 `S₀ = 1025.5511136843` 세 점으로 **정확히** 풀린다
(Brier는 예측 섭동의 정확한 2차식이라 근사가 아니다). `ΔS₁ = S₁−S₀`, `ΔS₂ = S₂−S₀`:

```
S(w) = S₀ + a·w − C·w²
C  = (ΔS₁·0.12 − ΔS₂·0.05) / 0.00042        [= w₁w₂(w₂−w₁)]
a  = ΔS₁/0.05 + C·0.05
w* = a/(2C)        G = a²/(4C)        배포 예상 = S₀ + G
```

빌드:
```
python submission/build_lgbm_ensemble.py --ens9 --calib 1.14202,-0.00264162 --calfitted \
  --segprobe gtF --segt 0.0057 --segfitted \
  --partner results/codex_partner/serving --wpartner <w*> \
  --partnermoments 0.4680607,0.0441981 --tag pwStar
python submission/verify_submission.py submission/dist/submit_pwStar.zip --proxy 245789
```

**중단 조건**: `C ≤ 0`(볼록성 위반) → 레그 비동일 의심, 역산 중단. `G < 2` → 배포 생략하고
슬롯을 월 축으로 돌린다. `w* > 0.7` → 파트너가 우리보다 강하다는 뜻이라 재검토(그럴 리 없다).

**참고 추정 `C ≈ 745`** (프록시 실측 RMS 0.0215@w=0.5에서 유도). ⚠ 프록시는 우리 레그의
당해시즌 피처를 무력화하므로 이 값은 어림수다. **세 점이 C를 실측하므로 가정에 의존하지 않는다.**

## 3. 슬롯 ④⑤ — **두 번째 파트너**(트랙맨) 프로브, `pwStar` 베이스 위에서

**아핀 재프로빙은 미룬다.** 정규화가 평균·분산 보존이라 캘리가 크게 흔들리지 않고, 모델 쪽
변경이 다 끝난 뒤 **한 번만** 다시 잡는 것이 슬롯 효율이 높다(D-58 도구 `--invert-slope`/`--invert`).

**파트너 P1이 죽었으면**(G < 2) exact1이 챔피언으로 남는다:
