# 21. 당해 시즌 성적 분리 — Program C가 가리킨 신호를 합법적으로 취하다

*(코드 `sweep/inseason.py` · `sweep/inseason_full.py`, 산출물 `results/inseason/`. D-28)*

## 0. 한 줄

`asof_*`는 **커리어 누적**이고 2025 서버 안에서 **계속 갱신된다**(실측 확인). train으로 만든
**"직전 시즌 말 누적" 룩업을 빼면 그 투수의 당해 시즌 성적만 분리**된다.
3폴드 **+123.0**(위약 −4.9), june 기준선 707.90 → **801.25**.
**이 프로젝트에서 june853 레시피 발견 이후 가장 큰 신호다.**

## 1. 어디서 나왔나

Program C(문서 20)가 "412점 웅덩이는 없다"를 확정하면서, 동시에 **P-A가 무엇을 먹고 있었는지**를
특정했다 — **투수 자신의 당해 시즌 성적**. 그건 라벨이라 2025에서 얻을 수 없다.
**그런데 그 일부는 주최가 이미 주고 있었다.**

`asof_pitcher_n`은 커리어 누적이고(A-2 검증: 투수 내 100% 단조 +1), `asof_pitcher_success_rate`는
그 시점까지의 커리어 성공률이다. 한 행에서 커리어 성공 수 `k = rate·n`이 정확히 복원된다.
여기서 train으로 만든 직전 시즌 말 누적 `(n_base, k_base)`를 빼면:

```
is_n     = n − n_base                     그 투수가 이번 시즌 던진 수
is_k     = k − k_base                     이번 시즌 성공 수
is_sm    = (is_k + K/2)/(is_n + K)        행 단위 수축 (K=200)
is_delta = is_sm − p_sm500                ← 당해 폼 − 커리어. 본체
is_share = is_n / n                       당해 비중 (신뢰도)
```

**`pitcher_id`는 june 레시피에서 제거돼 있으므로 트리는 이 값을 원리적으로 만들 수 없다.**
커리어 누적 rate는 이력에 희석돼(베테랑은 2025분이 10% 미만) 당해 신호를 드러내지 못한다.

## 4. z_asof(2025 −192)와 무엇이 다른가

둘 다 "train에서 만든 룩업"이지만 실패 형태가 정반대다.

| | z_asof (D-14 채택 → D-19 −192) | **is4** |
|---|---|---|
| 룩업 내용 | 투수별 **수축된 레벨** | 투수별 **직전 시즌 말 누적(카운터)** |
| 학습/서빙 구성 | 다름(train 전체로 만든 표를 val에 적용) | **동일**(시즌 s 행의 base는 항상 s−1 말) |
| 분포 이동 | 시즌마다 누적이 커져 out-of-support | `is_n`이 **매 시즌 0에서 시작**해 같은 범위 |
| 위약 대조 | 없었음 | 있음, 명확히 분리 |

**구조적으로 드리프트가 불가능하다**는 점이 결정적 차이다.

## 5. 규정 적합성 (§5)

- **행 단위 산술 + 동봉 룩업만** 쓴다. test 행 간 참조 없음.
- 룩업 = `{pitcher_id: (n_end2024, k_end2024)}` ≈ 800 엔트리. SERVE 블록에 dict 리터럴로 동봉.
- 배치 통계 연산 0 (`mean/groupby/...` 호출 없음) — AST 검사 통과 대상.
- 룩업에 없는 투수 → `(0, 0)` ⇒ `is_n = 커리어 n`. **정의상 옳다**(신인에겐 커리어가 곧 당해).
